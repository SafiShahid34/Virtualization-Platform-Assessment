2 · Requirements

Every option delivers the same six things

Options are only comparable if they do the same job. Each one meets all six requirements, and whatever it needs to get there, including third-party software and hardware, is in its cost.

Own desktopEach of 240 users keeps a personal Windows 11 VM (232 assigned, 8 floating).
Thin clientsAt work, the existing thin clients connect straight to the user's VM.
Home accessA web portal on a personal computer, with Duo sign-in.
Optimized Teams callsAudio and video handled on the endpoint, not inside the VM. Users rely on Teams heavily.
Servers and storage40 server VMs, highly available, with 32 TB usable for all VMs (double today's 16 TB).
Supported hardwareVendor-supported for all five years, with capacity to lose one host.
Ruled out: Microsoft RDS and free or low-cost RDP portalsMicrosoft's Teams optimization supports Azure Virtual Desktop, Windows 365, Citrix, Omnissa Horizon and Amazon WorkSpaces, not plain RDP. Remote Desktop Services, UDS Enterprise and Apache Guacamole would leave every call running inside the VM, so Hyper-V and Proxmox keep Horizon as the broker instead.

Hardware plan

The on-site options run the same workload (664 vCPU and 2.6 TB of RAM), so they share one plan. Desktops are sized at 2 vCPU / 8 GB and servers at 4 vCPU / 16 GB on average. The sizing is deliberately lean, matching how the environment runs today.

6 · Recommendation

Hyper-V + Horizon costs the least, with two strong alternatives

All three Horizon options keep Teams optimized and change nothing for users. They differ in five-year cost, in how much hands-on work the desktops need, and in how much has to be migrated.

Hyper-V + Horizon · lowest cost
$488,285
Proxmox + Horizon · certified by Omnissa

VMware · no migration

Hyper-V + Horizon: lowest cost, more hands-on work. It reuses the Windows Server Datacenter licenses and SAN already owned, so there's no hypervisor subscription, and it costs $138,041 less than staying on VMware. The trade-off is how desktops are managed. On Hyper-V, Horizon works through manual pools: every desktop is built, patched and kept running from templates and scripts outside Horizon, with no instant clones or automatic power management. For a one-person team, that's ongoing work the current setup handles automatically.

Proxmox + Horizon: the certified alternative. It costs $35,845 more, for the Proxmox subscription and training. In return, Omnissa certified Proxmox under its Horizon Ready program in September 2026, so Horizon on Proxmox has a vendor-backed support path. Proxmox is open source, thoroughly documented and backed by a large community, and its templates, cloning and full API make building desktops at scale easier. Its pools are manual too, so it suits a team that values certified support and documentation over the lowest price.

Staying on VMware: no migration. It costs $138,041 more over five years, but nothing moves. There are no 280 VMs to rebuild or convert and no retraining, and Horizon keeps its automated pools and power management. Migration labor isn't in any total, so the real gap is smaller than the numbers show. It's the right call if the team can't take on a migration in the next year.

The Azure options cost more ($505,368 on Azure Local, $867,043 in the cloud) and give every user a new client and portal.

Before committing

  1. Estimate the migration effort for Hyper-V and Proxmox, in internal hours or a partner quote, and weigh it against staying on VMware.
  2. Pilot ten users on the chosen platform: Teams calls, peripherals, and home access with Duo.
  3. Confirm each thin-client model has a supported Horizon client with Teams optimization.
  4. License Windows VDA for the 240 thin clients, and add 16 TB usable to the SAN.
  5. Quote the two Year-2 hosts early, since memory prices are volatile.
